# Recreation notes

`recreation/` plays the same hot-seat rules as the 2012 app and uses copies of the original PNGs. The visible rough edges that come from the Objective-C are kept on purpose: the move label starts at the xib's `"1"`, combat text uses raw type strings such as `blue2 lost attacking redbomb`, a tie prints `em and <defender> defeated ` because that is the order of the statements in `touchesEnded:`, a flag capture ends the game without moving either piece, and `endGame` leaves the current sprites in place while it changes the background and the console.

Where this page differs from the app:

1. It is a static web page (HTML, CSS, and one JavaScript file). There is no UIKit, no Xcode build, and no network request. Paths are relative so the folder can be hosted from any directory, including `file://`.
2. The stage is the portrait iPad layout: 768×1024 points, with a 20-point strip for the status bar and a 768×1004 view under it, matching `ViewController.xib`. The stage scales down to fit the browser window and is never scaled above its native size. The original `shouldAutorotateToInterfaceOrientation:` returns YES for every orientation, and the plist lists all four iPad orientations, but the xib frames are absolute portrait coordinates and the controller never lays them out again. This page does not simulate that rotation.
3. The status bar is a blank black rectangle. The xib simulates `UIStatusBarStyleBlackOpaque`. The clock, carrier, and battery are system chrome, and they are not drawn here.
4. The buttons approximate `UIButtonTypeRoundedRect`: Helvetica Bold 21, title color `rgb(50, 79, 133)`, a light vertical gradient, an 8-point corner radius. A pressed button darkens. That artwork is CSS, not the UIKit button. `white-space: pre` keeps the leading space in `" Set Move"` and `" Show Pieces"`.
5. The font stack is `Helvetica, "Liberation Sans", Arial, sans-serif`. Machines without Helvetica, including the one that took the screenshots, use the fallback.
6. The console is a `div` with the xib frame `{{218, 776}, {333, 44}}`, white background, black centered 21-point text, and it is not editable. Top padding is 8 points, in the neighborhood of a `UITextView` text inset. Side padding is 6 points.
7. The square you press gets a white outline. The app draws no selection. `Piece.imageView` is never assigned, and the body of `touchesMoved:` is commented out, so there is no drag sprite either. This page also accepts a second click on the destination, in addition to the original press-and-release gesture, so a mouse can play.
8. Releasing outside the 10×10 grid cancels the gesture. `BoardView`'s `pixelToCoordinate:` returns `(0, 0)` when the point misses every square.
9. After `endGame`, board presses do nothing. The app has no game-over flag. `touchesEnded:` can still move a piece when `player_turn` and `moveCount` line up, including after a resign that has just stored the other player in `player_turn`.
10. The dark margin around the stage, the footer ("Web recreation of a 2012 iPad class project, using the original sprites"), and the `noscript` line are only on the web page. The product name is not drawn in the page UI. The app does not draw it either. The browser tab icon is `darksquare.png`, so a host does not get a request for a missing favicon. The app has an empty `CFBundleIconFiles` array and no icon.
11. Sprites live in `recreation/sprites/` and are byte-for-byte the PNGs the Xcode target copies into the bundle (ranks 4–9, bombs, and flags via the `../` references in `project.pbxproj`; the rest from `StrategoGame/`). Bomb PNGs are 75×75. They are painted in the 70×70 views the app creates from the square image. `setImage:` does not resize those views.
12. Hits use the 70-point grid. In the app the board view is given `CGRectMake(0, 0, -60, -400)` and then sent `init` again, which replaces that frame with `CGRectZero`; `setCenter:(70, 70)` is what places it. Tiles are centered on multiples of 70, so the visible board is `(35, 35)`–`(735, 735)` in the 1004-point view. The page uses that rectangle and does not reimplement the `-35` scan in `pixelToCoordinate:`.
13. The flag test compares type strings. The app uses pointer equality (`==`) against `@"redflag"` and `@"blueflag"`. `createFlag:` assigns those literals, so the pointer compare succeeds in the binary. The outcome on screen is the same.
14. Several structures with no effect on `show:` are not rebuilt: the extra objects `setPiece:` inserts past index 9, the `BoardModel` allocated in `strategoGame`'s `init` and then replaced, the unset `imageView`, and the swapped arguments to `getSquareImage:` inside `takePiece:`.
